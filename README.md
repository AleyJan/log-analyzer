# Log Analyzer

A tool that takes a messy server log file and produces useful, on-call-friendly output — error patterns, slowest endpoints, traffic by IP, and a clear account of every line it couldn't parse.

It is built to handle real-world logs: mixed timestamp formats, different response-time units, missing status codes, appended user-agent fields, JSON lines bolted on midway, and outright garbage (stack traces, partial writes, blank lines). **It never crashes on bad input — malformed lines are skipped, counted, and surfaced with their line numbers, never silently dropped.**

The same parsing/analysis engine powers two interfaces:

- **CLI** : point it at a file, get a colored terminal report.
- **Web dashboard** : upload a file, explore the results visually.

---

## Quick Start (CLI : fastest way to evaluate)

Requires **Node.js 18+** (no other install needed for the CLI).

```bash
# 1. clone / unzip the repo, then from the project root:
node scripts/generate-logs.js     # creates sample.log (a representative messy log)
node cli.js sample.log            # analyze it
```

To run against your own file:

```bash
node cli.js /path/to/your/file.log
```

That's it. The CLI has zero dependencies, it uses only Node's built-in modules.

## Web Dashboard (optional, for visual exploration)

The dashboard needs two processes: the backend API and the frontend.

### 1. Backend

```bash
cd backend
npm install        # express, cors, multer
node index.js      # starts API on http://localhost:3001
```

### 2. Frontend (in a second terminal)

```bash
cd frontend
npm install        # or: yarn
npm run dev        # or: yarn dev — starts on http://localhost:5173
```

Open **http://localhost:5173**, drag in a log file, and explore.

## Generating Test Data

Since no sample file ships with the assessment, `scripts/generate-logs.js` produces a representative log including all the documented deviations:

```bash
node scripts/generate-logs.js
```

This writes `sample.log` (2,000 lines by default) with roughly:

- 80% well-formed lines
- 10% JSON-formatted lines
- 10% malformed lines (blank lines, stack traces, Apache-style lines, partial writes, garbage)

Within the well-formed lines it mixes four timestamp formats (ISO 8601, slash, named-month, Unix epoch), three response-time units (`142ms`, `0.142s`, `142`), missing status codes (`-`), and appended user-agent strings.

To change the size, edit `TOTAL_LINES` at the top of the script.

## What It Reports

| Section                | What it tells you                                                         |
| ---------------------- | ------------------------------------------------------------------------- |
| **Overview**           | Total requests, total errors, error rate, skipped-line count, time span   |
| **Status breakdown**   | Counts grouped into 2xx / 3xx / 4xx / 5xx, plus per-code counts           |
| **Slowest endpoints**  | Average + max response time per `METHOD path`, normalized to ms           |
| **Top endpoints**      | Most-hit endpoints and how many errors each produced                      |
| **Top IPs**            | Busiest clients and their individual error rates (spot abusers)           |
| **Requests over time** | Per-minute traffic histogram (web dashboard)                              |
| **Skipped lines**      | Every unparseable line, grouped by reason, with line numbers and examples |

## Design Notes

- **Graceful degradation is the core principle.** The parser returns `{ parsed, skipped }`. Nothing is ever dropped silently — every skipped line keeps its line number, raw content, and a reason.
- **Normalization.** All timestamps become JS `Date`s, all response times become a number in milliseconds, all status codes become numbers (or `null` when missing). Downstream analysis never has to think about input format.
- **Performance.** Tested on a generated **300,000-line (17 MB)** file: full parse + analysis in **~1.7 seconds**. This covers the assessment's stated maximum comfortably.
